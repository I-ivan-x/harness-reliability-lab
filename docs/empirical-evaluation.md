## 3. 前缀缓存分块量化律与思考预算帕累托

**核心结论：揭示服务端 `cached_tokens = 56 + 256k` 粗粒度页对齐规律与请求头切换击穿机制；实施动静分离前缀对齐并启用强制工具输出通道后，未见新题首轮缓存命中率升至 `75.01%`–`96.66%`，单题推理延迟降低 `48.67%`，并确立带外串行顾问 `p_rec < 45%` 的盈亏平衡边界。**

### 3.1 780 次请求前缀缓存审计与 `56 + 256k` 页对齐律

审查主基准全部 `780` 次请求（双模型各 `390` 次）后，我们首先排除了“工具定义顺序随机漂移”与“追加消息回溯失效”两项假说：代码中工具列表顺序固定不变，且同一次运行内第 2 至第 4 轮均能稳定复用前序缓存。真正的分水岭在于服务端 KV 缓存页的物理分块粒度：

- **Model A（`64` 词元细粒度分块）**：`390` 次调用零未命中，`cached_tokens` 严格落在 `64` 的整数倍（`128, 768, 896..1664`），整体前缀命中率达 **`80.11%`**。
- **Model B（`56 + 256k` 粗粒度页量化）**：`390` 次调用出现 `151` 次零命中（其中首轮跨题零命中 `72` 次）；所有内部页命中值精确服从线性方程：

```text
cached_tokens = 56 + 256k  (k ∈ Z+)
```

主基准 `780` 次请求集中命中 `k = 4, 5, 6`（对应 `1080, 1336, 1592` 词元，分别命中 `141`、`12`、`4` 次）；后续扩展对齐实验进一步精确验证了 `k = 9, 10, 12`（对应 `2360, 2616, 3128` 词元）。主基准首轮跨题频繁失配的根因有二：一是系统提示词尾部拼入了逐题变化的 `target_ref`，直接污染了第 `4` 个 `256` 词元缓存页末尾；二是受控对比证实，即使消息文本完全相同，切换请求级 `thinking` 参数也会改写服务端模板头部的思考控制词元，破坏 `56` 词元头部偏移与后续 `256` 词元缓存页边界对齐，导致跨模式首轮整段前缀缓存失效重算。

### 3.2 四臂受控帕累托实验与顾问盈亏平衡律

在 `artifacts/nextgen-v1-m2a-m3-pareto` 中，我们在 `8` 道代表性任务（`6` 道版本失效压力题 + `2` 道控制题，每题重复 `2` 次）上设计四组对照臂，先明确各组控制的单一工程变量：

1. **未对齐文本基线组（`G0`）**：沿用主基准尾部含动态 `target_ref` 的系统提示词、文本 `json_object` 终态通道与默认思考配置；
2. **动静分离与强制工具通道组（`G1`）**：将通用规则扩展为跨题恒定的静态前缀以锁死整页边界，将动态 `target_ref` 下沉至用户消息，用显式工具 `submit_disposition()` 统一终态输出并设置 `tool_choice="required"`，同时保留默认思考请求头以避免跨模式头部重算；
3. **显式关闭思考头对照臂（`G2`）**：保持与 `G1` 完全相同的对齐前缀与强制工具通道，但显式传入 `thinking={"type": "disabled"}` 请求头；
4. **零思考执行器与带外串行顾问组（`G3`）**：常规轮由零思考执行器快速推进，仅当遭遇 `STALE_REVISION` 恢复时串行发起一次低思考预算的带外顾问（Advisor）请求生成修正建议。

实验确立两条关键工程结论：

- **强制工具通道隐式归零思考开销（`G1` 全区间帕累托最优）**：在结构化工具决策场景下，`G1` 通过 `tool_choice="required"` 直接将隐式推理词元压至 `0`，同时避开了 `G2` 切换请求头引发的首轮缓存重算，未见新题首轮命中率从主基准新题首次出场的 `0%`（四臂未对齐基线 `G0` 为 `64.32%`）跃升至 `G1` 的 **`75.01%`** 与同请求头连续热态 `G3` 的 **`96.66%`**，单题平均推理延迟从 `9.213s` 降至 **`4.729s`（削减 `48.67%`）**。
- **带外串行顾问的盈亏平衡不等式与选型分野**：在 `G3` 的 `12` 次版本失效恢复中，执行器本体平均耗时 `5.2929s`（与 `G1` 的 `5.2991s` 基本重合），而每次独立带外顾问调用平均增加 `Δ_adv = 5.0815s` 往返开销；常规轮关闭长思考平均每题节省 `Δ_think = 2.2319s`。设异常恢复触发概率为 `p_rec`，则按需串行顾问相对“全程开启思考单智能体”取得净收益的充要条件为：

```text
p_rec · Δ_adv < Δ_think  ⇔  p_rec < (2.2319 s) / (5.0815 s) = 43.92%（约 45%）
```

这一定量边界明确了架构选型准则：在规则明确的结构化工具任务上，零思考 `G1` 全区间帕累托占优；而面对零思考执行器难以独立收敛的复杂多约束恢复场景，`G3` 在保住常规流量零思考速度与 `85.33%` 高缓存命中率的同时，将串行顾问开销严格收敛在 `<43.92%` 的低频异常尾部。压力测试集人为设定 `75%` 故障率越过了 `43.92%` 阈值，使串行往返开销抵消了常规轮节省；在 `18` 题主基准配比（`33.3%`）及常规生产异常率（`< 10%`）下，按需顾问均显著快于全程思考基线。
