# G0-3 单写槽位与幂等语义

G0-v1 · 2026-11-06 · 基于 `harness-plan-v1`；第 3/3 页。

**I1 固定身份。** 接纳任务时，Host 从可信启动配置绑定主体/权限、公开 `target_ref`、唯一 `run_id` 和槽位 `write-0`；`operation_id=(run_id,write-0)` 的固定编码即幂等键。每 run 最多一个逻辑写操作、一个新效果。模型只提案，不能修改保护字段、另开槽位或重置额度；服务端独立核对预授予的主体/槽位/目标，不信任模型自报身份。模型越界字段应拒绝，不静默改写为合法值。

**I2 参数。** `create_ticket` 业务参数为固定目标及 `expected_revision, queue, priority`；目标不可改，其余仅在下述修参窗口内可改。规范化采用 schema 校验后的类型值和稳定 JSON 键序，不做自然语言/大小写/空白的语义合并。request ID、模型 call ID、attempt、deadline 等传输字段不参与参数相等判断；所有尝试共用原键及累计额度。

| 槽位情况 | 服务端结果及允许变化 |
| --- | --- |
| 未绑定，参数/权限未通过 | 不保存业务参数绑定、不写效果；仅可信可修错误可按 P2 改授权字段 |
| 校验通过，进入短事务 | 当前状态校验、参数绑定、工单效果、成功回执原子提交；失败则整体回滚 |
| 已提交，同键同参 | 返回保存的原回执；不新增效果、不重新校验当前业务版本 |
| 已绑定，同键异参 | 明确拒绝；包括结果未知或两个异参请求竞争 |
| 有其他可能提交的旧请求 | 不签发整个槽位的可修声明；超时/取消通知不清除在途事实 |

**I3 顺序与竞争。** 一个 MCP 子进程、一个 SQLite 连接、一个进程内互斥入口。先验主体/归属/回执读权，再查既有绑定：已提交同参重放；否则才做当前写权限/参数/版本校验。查绑定到新执行处于同一受保护顺序；数据库唯一约束限制槽位唯一效果。等待互斥不占数据库事务；事务内无 `await`、模型调用或故障等待，屏障在事务前或提交后。意外数据库错误回滚并以 `SYSTEM_FAILURE` 收尾，不重开修参窗口。

同键请求可并发到达，后到者在自身截止时间内等待，再读取原回执；超时保持未知，不开启第二份效果。异参竞争以首个通过校验并原子绑定者为准，不承诺公平顺序。内存登记所有已接纳、尚可能提交的请求，含事务前延迟的旧请求；只有其他请求结束/确定不能提交且槽位未绑定，才能返回整槽位可修声明。不建持久 `PROCESSING`、租约或恢复服务。

**I4 回执与生命周期。** 回执至少含 `receipt_id, run_id, operation_id, target_ref, ticket_id, params`，与效果同事务保存，原内容不可覆盖。新 run 使用新目录、进程和数据库；运行内不删键、不复用环境另开 run 绕预算。提交后丢回执/取消不回滚效果；按故障规格收尾后封存台账。首版只承诺本地单操作至多一次提交与可重放回执，不承诺 Host 崩溃续跑或通用 exactly-once。

**手推 C（提交后丢回执，非实测）。** 同键 k、参数 p：写 1 原子提交 T1/R1 → 响应丢失，Host 只见超时，认知 `UNKNOWN` → P1/P2 写 2(k,p) → 验主体/读权，查到绑定，直接返回原 R1 → 实际反馈并引用 R1，完成；写尝试=2、效果=1。P0 不重放，诚实停止仍未知，可完成题正确=0；若所有回执均丢失，P1/P2 也不得由数据库补成成功。未知时换参数/换键均拒绝。
